### Gameplay preservation requirements

- `main.ts` imports global CSS and boots `game.ts` against `#app`. `game.ts` owns mutable closure state, DOM events, timer, queue, settings and overlays. Root `index.astro` currently contains the entire game and settings dialog. Defaults: Africa, Beginner, learning off. Settings order: Africa, South America, USA, Europe.
- `config.ts`: Beginner = 10 seconds per target, Middle = 5, Expert = 3. One shared round budget is target count × seconds per target; there is no per-answer timer, bonus time or penalty time.
- Start/replay copies and Fisher–Yates shuffles the full region array using `Math.random()`. The first remaining entry is the target. Correct guesses remove that entry and add its ID to the guessed set. Wrong guesses leave queue, score and time budget unchanged, show error feedback and select the input text. Submit checks timeout before accepting a correct answer; expiry wins at zero. The form's `required` attribute blocks an empty native submission.
- Skip rotates the target to the queue tail, clears input and error feedback, and awards no credit or penalty. With one target left, it remains the target. Command index is `min(guessed + 1, total)`, not number of attempts/skips; identified progress is zero-padded guessed count / total.
- Timer uses `performance.now()` and a 200 ms interval. Display uses `ceil`, clamps at zero, formats `MM:SS`, and becomes urgent at 30 seconds or less. Finish clamps elapsed to round duration. Completing the queue finishes immediately; timeout sets displayed remaining time to zero. No numeric points, streak or speed bonus exists: score means correct count and coverage (`Math.round(correct / total * 100)`).
- Exit button or non-repeated Escape opens a native modal after checking expiry. It stops ticks, hides learning tooltip and focuses Continue. Continue or dialog cancellation excludes time spent paused and focuses the answer. End game discards progress, restores full timer and returns to retained settings, without results. Ordinary tab hiding currently does not pause time; refresh loses the session. These last two behaviors change explicitly under the persistence contract.
- Results show completion/timeout copy, total, guessed, not guessed, rounded coverage and ratio. Completion copy includes formatted elapsed time; timeout copy does not. Replay retains region, level and learning but reshuffles. Change settings returns to retained selections. Migration adds explicit region/difficulty and elapsed reporting for both outcomes; do not invent a scoring system.
- No Atlas Rush sound effects exist. Preserve feedback text intent, focus recovery, reduced-motion support, dark grid/radial background, monospaced telemetry, violet unguessed shapes, amber target and cyan identified shapes. Port scoped styling to CSS Modules without changing unrelated global styling.

### Session and rendering contract

Phases are `ready | playing | paused | finished`. Store actions are `startGame`, `submitGuess`, `skipCountry`, `pauseGame`, `resumeGame`, `finishGame`, `resetGame`, `restoreGame`. Domain guards reject gameplay actions outside playing; timeout is evaluated before answer/skip/pause. Restore validates before installing state. Keep current target derived from `remainingIds[0]`, count from guessed IDs, and duration from region/level. If a snapshot records redundant target/count fields, validate their consistency.

Store session uses config, ordered remaining IDs, guessed IDs, duration/elapsed checkpoints and finish reason. Wrong-answer feedback is a transition outcome consumed by input UI, not a scoring field. Reusable results include region, level, learning, seed, correct/total, coverage, elapsed and completion/timeout. Preserve only score-relevant facts; no attempt penalty.

The running monotonic anchor is ephemeral runtime state. Timer display samples it locally; the only timer-driven gameplay update is expiry. No global state update every frame/character. Memoize expensive map geometry where needed and test that paths are not recreated on typing/ticking. Tooltip/hover/focus/answer stay local. Effects, timers, subscriptions and listeners must clean up, including React development remounts; no DOM mutation inside React-owned SVG.

### #21 implemented domain contract and #22 handoff

- Implemented `domain/{types,answers,levels,shuffle,session,time,results}.ts` and `data/{regions,targets}.ts`. Domain runtime imports only pure TypeScript modules and geometry-free metadata. `regionTargets` preserves the exact legacy ID/name/source order for all 163 targets. Metadata parity tests temporarily import legacy geography **only in tests**; runtime consumers do not. SVG files and learning interaction are unchanged.
- `ChallengeConfig` is the typed `{ regionId, level, learning, seed }` contract. Domain callers supply valid configuration; URL validation/defaulting remains #24 and untrusted snapshot validation remains #26/#27. `challengeVersion = 1`, `defaultSeed = 'atlas-rush-v1'`. FNV-1a hashes ASCII seed character codes with `Math.imul` and unsigned 32-bit output; Mulberry32 wraps state at 32 bits, divides unsigned output by 2^32, and drives descending Fisher–Yates. Full default-seed permutations for every region are locked in tests. Seed generation and browser adoption are not part of #21.
- `createSession(config)` creates ready state; `startGame(config)` creates playing state; `resetGame(session)` returns ready with the same settings and initial seeded queue. Session stores only config/version, phase, remaining/guessed IDs, duration, elapsed checkpoint and nullable finish reason. Current target and command index are derived. `submitGuess` returns `{ session, outcome, targetId }`; outcome is `ignored | incorrect | correct | timeout`, with no persisted feedback or typing. Wrong guesses return the original session. Correct guesses, skip and pause checkpoint active elapsed time; unrelated ID arrays retain their references.
- **Time API:** every optional `elapsedSeconds` argument is **total active seconds since round start**, not a timestamp or a delta since the previous action. Defaults use the session checkpoint. Caller/store computes checkpoint + active interval from its injected monotonic clock, reanchors when accepting a new checkpoint, and excludes paused time. An incorrect/ignored action does not install a new checkpoint, so do not discard its still-running anchor. Time calculations clamp to the checkpoint/duration, ignore NaN, and ignore supplied time outside playing. No domain function reads a clock, schedules ticks or stores monotonic anchors.
- `finishGame(session, elapsedSeconds)` finishes only playing sessions on expiry or an empty queue. Expiry wins before guess/skip/pause and elapsed time is capped at duration. Pause/resume retain exact queue and time; reset handles exit-to-settings without results. `getResults` returns null until finished, then reusable config/version, correct/total/not-guessed, rounded coverage, elapsed and completion/timeout. There are no points or time penalties.
- Legacy `answers.ts`, `config.ts`, `types.ts`, `regions.ts` and `components.ts` now bridge shared answer rules, levels/budgets, domain types, region metadata, time formatting and coverage. `game.ts` keeps its existing browser lifecycle, random shuffle and transitions until the planned UI migration; no root UI switch or geometry relocation occurred. #22 should build its per-instance Zustand store on these domain functions, with injected clock and stable selectors, while retaining this legacy entry point. #23 owns geometry lazy-loading and React/browser tooling.

### Challenge URL and deterministic order

- Shared config: `{ regionId, level, learning, seed }`. Path determines region. Levels are `beginner | middle | expert`; learning accepts only `0 | 1`. Defaults are Beginner, false, seed `atlas-rush-v1`.
- Seed grammar decision: 1–64 ASCII characters matching `[A-Za-z0-9_-]+`, case-sensitive. Invalid/empty/missing/duplicated values fall back to the field's default. Reject malformed percent encoding; do not silently accept a partially decoded seed. Duplicated keys default even if repeated values agree. Unknown keys, including `region`, are removed.
- Serializer orders `level`, `learning`, `seed`, omits defaults, and retains valid nondefault seeds. Start and URL cleanup use this same contract. Players can share the current URL through their browser; there is intentionally no in-game copy action. `/africa/?level=bad&learning=1&foo=bar` becomes `/africa/?learning=1`, staying in Africa. Browser cleanup uses `history.replaceState` without reload and may give a nonblocking notice.
- Shuffle v1 decision for #21: hash seed with 32-bit FNV-1a using `Math.imul`, feed Mulberry32, and run descending Fisher–Yates on the preserved source ID order. Lock numeric operations and golden permutations in tests before adoption. Same region/seed means same initial queue regardless of level/learning. `challengeVersion = 1` covers ID order, geography membership and algorithm; changing these later requires an explicit compatibility decision, not silent link drift.
- Plain URLs never randomize. Intentional new randomized challenges generate a safe explicit seed in browser infrastructure before serializing. Replay keeps settings and generates that seed to preserve the old reshuffle intent; “Start new” on a matching-save prompt discards progress and starts the same URL challenge from its initial order. URL is config only, never progress.

### Persistence and mobile boundaries

#### #26: IndexedDB and clock contract for #27

Use `idb` with database `atlas-rush`, database version `1`, and one object store `sessions` with `keyPath: 'key'`. The database version controls object-store upgrades; the independent `schemaVersion` below controls record interpretation. Database v1 creates the store; there are no legacy database records to migrate. The scope is this origin only. Never use `updatedAt` or wall-clock time to determine game time or write order.

**Challenge identity.** After path validation and the shared query parser, use the exact string `JSON.stringify([challengeVersion, regionId, level, learning, seed])` as `key`. Its components are the normalized values from `ChallengeConfig`, including default seed `atlas-rush-v1`, and challenge version `1`. JSON array encoding makes boundaries unambiguous; no path, query order, locale, target geometry or player progress participates. Different learning or level settings are different saves even when seed and region match. Recompute this key on load and require exact equality with the record and requested URL identity.

**Record v1.** One record per identity, with the following structured-clone-safe fields (all numbers are finite JavaScript numbers; IDs and seeds are strings):

```ts
type SessionRecordV1 = {
  key: string; // canonical identity above
  schemaVersion: 1;
  generation: string; // fresh opaque random token for a claimed run
  revision: number; // nonnegative safe integer, monotonic within generation
  updatedAt: number; // Date.now() milliseconds, informational only
  snapshot: null | {
    challengeVersion: 1;
    config: ChallengeConfig;
    phase: 'playing' | 'paused' | 'finished';
    remainingIds: string[]; // exact queue order
    guessedIds: string[]; // correct-answer order
    currentTargetId: string | null; // remainingIds[0] or null
    durationSeconds: number;
    elapsedSeconds: number; // total active seconds at capture
    remainingSeconds: number; // durationSeconds - elapsedSeconds
    correctCount: number; // guessedIds.length
    finishReason: 'completed' | 'timeout' | null;
  };
};
```

`null` snapshot is a durable tombstone, not a missing record. Do not store SVG paths, country objects, input text, tooltip state, clock anchors or `performance.now()` values. Snapshot values are captured together from one session and one clock sample. Redundant fields must agree exactly with their derived values; they are validation aids, not independently authoritative state. Duration uses the existing region target count and difficulty, and coverage is derived with `getCoverage`, never persisted as a separate scoring system.

**Validate before installation.** Treat every record and snapshot as untrusted: verify plain field types, supported versions, safe integer revision, valid finite timestamp, seed grammar and exact normalized config/identity; require the four known region IDs and the existing geometry-free target IDs for that region. The 54 Africa, 12 South America, 50 USA and 47 Europe targets must each occur exactly once across remaining and guessed arrays; reject unknown, missing, duplicate or cross-region IDs. Verify `currentTargetId`, `correctCount`, duration, finite time bounds and `remainingSeconds === durationSeconds - elapsedSeconds`. A playing/paused snapshot has remaining IDs, elapsed below duration and null finish reason. A completed snapshot has an empty queue and elapsed below duration; a timeout has remaining IDs and elapsed exactly duration. Apply `isValidSession` as a second domain check after adapting the record; it currently checks only that seed is a string, so explicitly apply `isValidSeed` before calling it. Do not silently drop stale IDs or reorder a queue.

**Initialization and migration.** Normalize the URL, load the selected geography, read the record and validate it before enabling gameplay. For a valid playing/paused snapshot, show Continue / Start new. Continue restores its queue and checkpoint paused, then establishes a fresh clock anchor when play resumes. Start new uses the same URL identity and seeded initial queue. Finished snapshots never offer Continue; present a new game instead. Tombstones and missing rows start new. A corrupt, obsolete or unknown-version record must not be installed; allow a new game, show a nonblocking storage notice and replace it only through a new-run claim. There is no older snapshot schema to migrate in v1: future migrations must be explicit per-version pure transforms, validate the transformed result, and commit it transactionally before restore. Unknown future database versions, blocked upgrades or migration failure fall back to memory-only play without deleting data. A change to shuffle or target membership requires an explicit challenge-version compatibility/migration decision; never reinterpret v1 silently.

**Ordering, restart and competing tabs.** A claim is one IndexedDB readwrite transaction on `sessions`: read the current row, create a cryptographically random generation token, and write revision `0` with either the validated snapshot being continued or a tombstone for Start new/reset. Commit the claim before enabling durable writes. On Continue, use the latest row read inside this transaction, revalidate it, and if it changed or became invalid while the prompt was open, refresh the prompt or offer a new game. Start new claims with a tombstone before writing the new session; the tombstone must not be deleted while another writer may exist. Serialize each tab's snapshot saves in event order. Each save transaction reads the row and writes only if the key and generation still match and its revision is greater than the stored revision; compare and `put` within the same readwrite transaction. A tab assigns consecutive revisions when captures are queued, and commits a full immutable captured snapshot. Await transaction completion, not merely `put`, before reporting a durable checkpoint. Guard safe-integer overflow by stopping persistence with a notice rather than wrapping.

A different tab explicitly choosing Continue or Start new claims a fresh generation, so later commits from the old tab fail the token check and cannot resurrect a discarded or newer run. The old tab may continue in memory, but must stop saving that identity and show a nonblocking notice; it must not automatically reclaim it. If a resumable snapshot exists, do not claim before the player's decision. When no resumable snapshot exists, direct launch may claim and start automatically, but must re-read the row in that transaction and show the prompt instead if another tab has since saved an incomplete run. If a row is absent after a claim, reject stale writes rather than recreating it. Reset/End game conditionally replaces the row with a fresh-generation tombstone only if the tab still owns the current generation; a tab that lost ownership must not erase the other tab's save. Commit the tombstone before leaving when possible; on failure, report that an older saved round may still be offered. IndexedDB eviction, transaction abort or process termination can still prevent any pending write from being durable.

**Monotonic clock and lifecycle.** In a playing session, calculate total active seconds as the domain checkpoint plus `(clock.now() - anchor) / 1000` using injected monotonic milliseconds. Capture once per event and clamp via the domain time functions; reanchor only when a new checkpoint is accepted. Wrong answers and timer display samples must not reanchor. #27 needs a store checkpoint operation that samples elapsed without changing queue/phase, checks expiry first and reanchors atomically; the current `getRemainingSeconds()` only reads and cannot create a checkpoint. Correct guess, skip, pause, resume, finish and start capture/save after the corresponding transition; no writes for typing, wrong answers or timer ticks. Serialize a playing checkpoint only with active elapsed time, never an anchor.

On `visibilitychange` to hidden, sample the clock immediately, finish if expired, otherwise pause and enqueue a best-effort save; remember only in memory whether this was an automatic visibility pause. On visible, resume and checkpoint only if that automatic pause is still current; do not resume a user-paused, finished or reset session. On `pagehide`, capture and enqueue a final best-effort checkpoint; duplicate hidden/pagehide notifications must not double-count time. A refresh, page close or abrupt termination restores at the last **committed** checkpoint, paused, regardless of the stored playing/paused phase. Time after the last durable capture may be lost and asynchronous pagehide work may never complete; do not charge wall time away or promise an unload save. Storage errors never block gameplay; keep current in-memory clock behavior and surface a nonblocking warning.

### Mobile input follow-up

- Atlas Rush uses a 16px root font on desktop and mobile. This overrides the browser's default font-size preference for the game; viewport breakpoints use CSS pixels so that preference cannot alter keyboard layout rules. The keyboard can scroll if a larger page font is applied.
- Switching keyboard modes recreates the answer input. Returning to the on-screen keyboard places its caret at the end; typing appends there or replaces selected text. Long answers stay scrolled to the caret, including after an orientation change. Keyboard touch actions do not cancel pointer-down events, allowing WebKit to dispatch their clicks.
