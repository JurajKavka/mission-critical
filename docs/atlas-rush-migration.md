### Gameplay preservation requirements

- `main.ts` imports global CSS and boots `game.ts` against `#app`. `game.ts` owns mutable closure state, DOM events, timer, queue, settings and overlays. Root `index.astro` currently contains the entire game and settings dialog. Defaults: Africa, Beginner, learning off. Settings order: Africa, South America, USA, Europe.
- `config.ts`: Beginner = 10 seconds per target, Middle = 5, Expert = 3. One shared round budget is target count × seconds per target; there is no per-answer timer, bonus time or penalty time.
- Start/replay copies and Fisher–Yates shuffles the full region array using `Math.random()`. The first remaining entry is the target. Correct guesses remove that entry and add its ID to the guessed set. Wrong guesses leave queue, score and time budget unchanged, show error feedback and select the input text. Submit checks timeout before accepting a correct answer; expiry wins at zero. The form's `required` attribute blocks an empty native submission.
- Skip rotates the target to the queue tail, clears input and error feedback, and awards no credit or penalty. With one target left, it remains the target. Command index is `min(guessed + 1, total)`, not number of attempts/skips; identified progress is zero-padded guessed count / total.
- Timer uses `performance.now()` and a 200 ms interval. Display uses `ceil`, clamps at zero, formats `MM:SS`, and becomes urgent at 30 seconds or less. Finish clamps elapsed to round duration. Completing the queue finishes immediately; timeout sets displayed remaining time to zero. No numeric points, streak or speed bonus exists: score means correct count and coverage (`Math.round(correct / total * 100)`).
- Exit button or non-repeated Escape opens a native modal after checking expiry. It stops ticks, hides learning tooltip and focuses Continue. Continue or dialog cancellation excludes time spent paused and focuses the answer. End game discards progress, restores full timer and returns to retained settings, without results. Ordinary tab hiding currently does not pause time; refresh loses the session. These last two behaviors change explicitly under the persistence contract.
- Results show completion/timeout copy, total, guessed, not guessed, rounded coverage and ratio. Completion copy includes formatted elapsed time; timeout copy does not. Replay retains region, level and learning but reshuffles. Change settings returns to retained selections. Migration adds explicit region/difficulty and elapsed reporting for both outcomes; do not invent a scoring system.
- No Atlas Rush sound effects exist. Preserve feedback text intent, focus recovery, reduced-motion support, dark grid/radial background, monospaced telemetry, violet unguessed shapes, amber target and cyan identified shapes. Port scoped styling to CSS Modules without changing unrelated global styling.

### Session and rendering contract

Phases are `ready | playing | paused | finished`. Store actions are `startGame`, `submitGuess`, `skipCountry`, `pauseGame`, `resumeGame`, `finishGame`, `resetGame`, `restoreGame`. Domain guards reject gameplay actions outside playing; timeout is evaluated before answer/skip/pause. Restore validates before installing state. Keep current target derived from `remainingIds[0]`, count from guessed IDs, and duration from region/level. If a snapshot records redundant target/count fields, validate their consistency.

Store session uses config, ordered remaining IDs, guessed IDs, duration/elapsed checkpoints and finish reason. Wrong-answer feedback is a transition outcome consumed by input UI, not a scoring field. Reusable results include region, level, learning, seed, correct/total, coverage, elapsed and completion/timeout. Preserve only score-relevant facts; no attempt penalty.

The running monotonic anchor is ephemeral runtime state. Timer display samples it locally; the only timer-driven gameplay update is expiry. No global state update every frame/character. Memoize expensive map geometry where needed and test that paths are not recreated on typing/ticking. Tooltip/hover/focus/answer stay local. Effects, timers, subscriptions and listeners must clean up, including React development remounts; no DOM mutation inside React-owned SVG.

### #21 implemented domain contract and #22 handoff

- Implemented `domain/{types,answers,levels,shuffle,session,time,results}.ts` and `data/{regions,targets}.ts`. Domain runtime imports only pure TypeScript modules and geometry-free metadata. `regionTargets` preserves the exact legacy ID/name/source order for all 163 targets. Metadata parity tests temporarily import legacy geography **only in tests**; runtime consumers do not. SVG files and learning interaction are unchanged.
- `ChallengeConfig` is the typed `{ regionId, level, learning, seed }` contract. Domain callers supply valid configuration; URL validation/defaulting remains #24 and untrusted snapshot validation remains #26/#27. `challengeVersion = 1`, `defaultSeed = 'atlas-rush-v1'`. FNV-1a hashes ASCII seed character codes with `Math.imul` and unsigned 32-bit output; Mulberry32 wraps state at 32 bits, divides unsigned output by 2^32, and drives descending Fisher–Yates. Full default-seed permutations for every region are locked in tests. Seed generation and browser adoption are not part of #21.
- `createSession(config)` creates ready state; `startGame(config)` creates playing state; `resetGame(session)` returns ready with the same settings and initial seeded queue. Session stores only config/version, phase, remaining/guessed IDs, duration, elapsed checkpoint and nullable finish reason. Current target and command index are derived. `submitGuess` returns `{ session, outcome, targetId }`; outcome is `ignored | incorrect | correct | timeout`, with no persisted feedback or typing. Wrong guesses return the original session. Correct guesses, skip and pause checkpoint active elapsed time; unrelated ID arrays retain their references.
- **Time API:** every optional `elapsedSeconds` argument is **total active seconds since round start**, not a timestamp or a delta since the previous action. Defaults use the session checkpoint. Caller/store computes checkpoint + active interval from its injected monotonic clock, reanchors when accepting a new checkpoint, and excludes paused time. An incorrect/ignored action does not install a new checkpoint, so do not discard its still-running anchor. Time calculations clamp to the checkpoint/duration, ignore NaN, and ignore supplied time outside playing. No domain function reads a clock, schedules ticks or stores monotonic anchors.
- `finishGame(session, elapsedSeconds)` finishes only playing sessions on expiry or an empty queue. Expiry wins before guess/skip/pause and elapsed time is capped at duration. Pause/resume retain exact queue and time; reset handles exit-to-settings without results. `getResults` returns null until finished, then reusable config/version, correct/total/not-guessed, rounded coverage, elapsed and completion/timeout. There are no points or time penalties.
- Legacy `answers.ts`, `config.ts`, `types.ts`, `regions.ts` and `components.ts` now bridge shared answer rules, levels/budgets, domain types, region metadata, time formatting and coverage. `game.ts` keeps its existing browser lifecycle, random shuffle and transitions until the planned UI migration; no root UI switch or geometry relocation occurred. #22 should build its per-instance Zustand store on these domain functions, with injected clock and stable selectors, while retaining this legacy entry point. #23 owns geometry lazy-loading and React/browser tooling.

### Challenge URL and deterministic order

- Shared config: `{ regionId, level, learning, seed }`. Path determines region. Levels are `beginner | middle | expert`; learning accepts only `0 | 1`. Defaults are Beginner, false, seed `atlas-rush-v1`.
- Seed grammar decision: 1–64 ASCII characters matching `[A-Za-z0-9_-]+`, case-sensitive. Invalid/empty/missing/duplicated values fall back to the field's default. Reject malformed percent encoding; do not silently accept a partially decoded seed. Duplicated keys default even if repeated values agree. Unknown keys, including `region`, are removed.
- Serializer orders `level`, `learning`, `seed`, omits defaults, and retains valid nondefault seeds. The parser, Start, Copy challenge link and cleanup use this same contract. `/africa/?level=bad&learning=1&foo=bar` becomes `/africa/?learning=1`, staying in Africa. Browser cleanup uses `history.replaceState` without reload and may give a nonblocking notice.
- Shuffle v1 decision for #21: hash seed with 32-bit FNV-1a using `Math.imul`, feed Mulberry32, and run descending Fisher–Yates on the preserved source ID order. Lock numeric operations and golden permutations in tests before adoption. Same region/seed means same initial queue regardless of level/learning. `challengeVersion = 1` covers ID order, geography membership and algorithm; changing these later requires an explicit compatibility decision, not silent link drift.
- Plain URLs never randomize. Intentional new randomized challenges generate a safe explicit seed in browser infrastructure before serializing. Replay keeps settings and generates that seed to preserve the old reshuffle intent; “Start new” on a matching-save prompt discards progress and starts the same URL challenge from its initial order. URL is config only, never progress.

### Persistence and mobile boundaries

#26 will specify the exact schema/transaction/checkpoint protocol needed by #27, building on these decisions. Snapshot identity is version + region + normalized level/learning/seed. Use `idb`; store ordered remaining/guessed IDs, config, phase, elapsed/remaining checkpoint, finish data and update timestamp, never paths/static objects or `performance.now()` values. Validate schema, version, membership, unique/disjoint queues, target and timing bounds. Different identities remain independent. Serialize writes or enforce monotonic revisions so delayed saves cannot overwrite newer state, including reset/start-new operations.

Initialization order: normalize URL → load selected geography/metadata → find and validate matching save → Continue / Start new for incomplete saves → begin/restore only after the decision. Keep initialization status separate from gameplay phase. Restore playing snapshots as paused at the last durable checkpoint; Continue establishes a new monotonic anchor. Save at start, correct, skip, pause, resume, finish and significant lifecycle transitions, never every tick/keystroke. Visibility/pagehide checkpoints are best effort; abrupt closure may lose work/time since the last reliable save. No charging time spent away. Storage failure falls back to playable memory state with a nonblocking message; obsolete/corrupt data must not trap initialization. Cross-tab and deletion races belong in #26's concrete contract.

#28 adds a mobile-only persistent A–Z QWERTY keyboard plus Space, Backspace, Enter and Skip **above the visible answer input** while playing. Desktop keeps native input only. Use responsive dimensions/pointer capability, not UA detection; preserve external keyboards. Keep a stable control area across typing, handle `dvh`, safe areas and orientation, maximize tall-screen map area and permit map overlap on short screens. Prevent unnecessary native keyboard activation and provide accessible “Use native keyboard”. Learning refocus must honor that choice. No keyboard implementation in #20–#27.

### #22 store contract and #23 handoff

- `createAtlasRushStore(config, clock)` creates an independent Zustand vanilla store. `clock.now()` supplies monotonic milliseconds. No timers, browser APIs, input text or persistence are stored. Call `getRemainingSeconds()` for display and `finishGame()` on a scheduled expiry check; neither requires a global tick update.
- Actions use the domain transitions and checkpoint active time on accepted changes.
